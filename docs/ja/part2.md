# Part 2: IBM Bob で機能を追加する

Part 1 では検索を動かしました。この Part では、その検索を変更します。コードは自分では書きません。

## この Part の目標

- やりたいことを普通の言葉で伝えて、機能を 2 つ追加する
- Building Block が回答に何を持ち込んでいるかを見る
- 指示 → 提案の確認 → 承認 → 動作確認、という進め方を身につける

## 進め方

1. **指示する** — どうやるかではなく、何が欲しいかを伝えます。
2. **提案を読む** — Bob は変更する前に、何を変えるつもりかを説明します。
3. **承認する** — 編集を受け入れるか、指摘して直してもらいます。
4. **動作確認する** — 自分でリクエストを投げて結果を確かめます。

4 は省略できません。ファイルを編集するエージェントであっても、責任を持つのは使う側です。

## 機能 1: 価格で絞り込む

買い手は予算で絞り込みます。いまの `/search` にはその手段がありません。

=== "IBM Bob IDE"

    **OpenSearch Vector Search Builder** を選んだ状態で、チャットに次のように入力します。

    ```text
    /search に上限価格の指定を追加してください。指定した価格以下の結果だけを返せるように
    したいです。3 つのモードすべてで効くようにしてください。
    ```

=== "Bob shell"

    !!! warning "確認中"

        Bob shell の手順はバージョン 2.0.4 の実機で確認中です。確認でき次第ここに記載します。それまでは IBM Bob IDE のタブをご覧ください。

### 回答のどこを見るか

ここが面白いところです。価格の絞り込みは簡単そうに見えますが、ハイブリッド検索では簡単ではありません。そしてモードはその理由を知っています。

- **キーワード**側の絞り込みは、`bool` クエリに句を 1 つ足すだけです。
- **ベクトル**側の絞り込みは、検索の**後**ではなく **k-NN のフィルター**として指定する必要があります。k-NN の結果を後から絞ると、グラフの探索がすでに見るベクトルを決めてしまっているため、`top_k` に満たない件数が黙って返ります。
- **ハイブリッド**では、同じ条件を両側に届ける必要があります。届かないと、2 つの順位付けが「何が対象か」で食い違います。

承認する前に提案を読み、ベクトル側について何か書かれているかを見てください。その知識は、質問の言い回しからではなく Building Block のルールから来ています。

### 動作を確認する

```bash
curl -s -X POST http://localhost:8002/search \
  -H 'Content-Type: application/json' \
  -d '{"query": "運動するときに履くもの", "mode": "hybrid", "max_price": 9000}'
```

返ってくる商品はすべて 9000 円以下のはずです。`max_price` を外した同じ質問も実行し、上限を超える商品が消えることを確かめてください。何も変わらない絞り込みは、効いていることを確かめたことになりません。

## 機能 2: なぜ一致したのかを説明させる

`hybrid` はすでに `keyword_score` と `vector_score` を返しています。この数値を人が読める形にします。

=== "IBM Bob IDE"

    ```text
    hybrid の結果に match_reason を追加してください。2 つのスコアをもとに、語が一致した
    のか、意味が一致したのか、その両方なのかを短く示すものです。
    ```

=== "Bob shell"

    !!! warning "確認中"

        Bob shell の手順はバージョン 2.0.4 の実機で確認中です。確認でき次第ここに記載します。それまでは IBM Bob IDE のタブをご覧ください。

### 動作を確認する

```bash
curl -s -X POST http://localhost:8002/search \
  -H 'Content-Type: application/json' \
  -d '{"query": "景色をきれいに写す道具", "mode": "hybrid"}'
```

キーワード検索では見つからなかった結果が、そのことを示しているはずです。

## 回答が間違っていたら

間違うことはあります。やり直させるより、どこが違うかを伝える方が早く済みます。

```text
フィルターが k-NN 検索の後に適用されているので、絞り込むと top_k より少ない件数しか
返りません。knn クエリの中で適用してください。
```

Bob は直前に編集したファイルの文脈を保持しているので、指摘は書き直しより安く済みます。変更を丸ごと捨てたいときは、`git diff` で何が触られたかを確認できます。

!!! tip "理由を聞いてみる"

    ```text
    なぜフィルターを検索後ではなく knn 句の中に入れたのですか。
    ```

    返ってくる説明は、Building Block のルールが k-NN のフィルターについて述べていることの要約になっています。一度読んでおく価値があります。

## いま起きたこと

ハイブリッド検索エンジンを、普通の言葉で 2 回変更しました。しかも変更が入ったのは、OpenSearch で間違えやすい箇所です。その専門知識は、IBM が配布していて、zip を展開するだけで導入できたモードから来ています。
