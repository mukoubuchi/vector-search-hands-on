# Part 2: IBM Bob で機能を追加する

Part 1 では検索を動かしました。この Part では、その検索を変更します。コードは自分では書きません。

## この Part の目標

- やりたいことを普通の言葉で伝えて、機能を 2 つ追加する
- Building Block が回答に何を持ち込んでいるかを見る
- 指示 → 変更内容の確認 → 動作確認、という進め方を身につける

## 進め方

1. **指示する** — どうやるかではなく、何が欲しいかを伝えます。
2. **作業を見る** — Bob はプロジェクトを調べ、とる方針を説明し、編集を適用します。
3. **適用された内容を読む** — パネルに変更したファイル数が出ます。**［すべて表示］** で差分を開き、意図と違えば **［すべて元に戻す］** で戻せます。
4. **動作確認する** — 自分でリクエストを投げて結果を確かめます。

3 と 4 は省略できません。Bob は先にファイルを編集して後から見せるので、差分を読むことがレビューであり、クエリを投げることが証拠になります。なお、コマンドの実行は編集とは扱いが違います。Bob がコマンドを実行したいときは、**［1 回だけ承認］** か **［拒否］** を尋ねて止まることがあります。

## 機能 1: 価格で絞り込む

買い手は予算で絞り込みます。いまの `/search` にはその手段がありません。

**OpenSearch Vector Search Builder** を選んだ状態で、チャットに次のように入力します。

```text
/search に上限価格の指定を追加してください。指定した価格以下の結果だけを返せるように
したいです。3 つのモードすべてで効くようにしてください。
```

Bob はプロジェクトを読み、とる方針を述べてから `app.py` に差分を適用します。

![方針を説明して app.py に差分を適用している Bob](images/part2-feature1-proposal-ja.png)

終わると、変更の要約と **［すべて表示］**・**［すべて元に戻す］** が出ます。

![適用した変更の要約と、すべて表示・すべて元に戻すのボタン](images/part2-feature1-applied-ja.png)

### 回答のどこを見るか

ここが面白いところです。価格の絞り込みは簡単そうに見えますが、ハイブリッド検索では簡単ではありません。そしてモードはその理由を知っています。

- **キーワード**側の絞り込みは、`bool` クエリに句を 1 つ足すだけです。
- **ベクトル**側の絞り込みは、検索の**後**ではなく **k-NN のフィルター**として指定する必要があります。k-NN の結果を後から絞ると、グラフの探索がすでに見るベクトルを決めてしまっているため、`top_k` に満たない件数が黙って返ります。
- **ハイブリッド**では、同じ条件を両側に届ける必要があります。届かないと、2 つの順位付けが「何が対象か」で食い違います。

**［すべて表示］** を開いて差分を読んでください。上のスクリーンショットを撮った実行では、3 か所とも正しく入っていました。

- `keyword_body` は `multi_match` を `bool` で包み、`filter` にレンジを足しています。ここに置くと、BM25 のスコアに影響を与えずに絞り込めます。
- `vector_body` は同じレンジを **`knn` 句の中**に入れています。グラフの探索が最初から条件を満たす文書だけを見る形です。
- `hybrid_hits` は両側に上限を渡すので、2 つの順位付けが「何が対象か」で食い違いません。

これらは指示文には書いていません。Building Block のルールから来ています。

!!! note "毎回同じ実装になるとは限りません"

    Bob はそのつど書き起こすので、補助関数の名前や構成は違うことがあります。変わらないでほしいのはフィルタを置く場所です。ベクトル側は `knn` 句の中、キーワード側は `filter` 句、hybrid は両側へ渡す、の 3 点です。

### 動作を確認する

```bash
curl -s -X POST http://localhost:8002/search \
  -H 'Content-Type: application/json' \
  -d '{"query": "赤いスニーカー", "mode": "hybrid", "max_price": 8000}'
```

返ってくる商品はすべて 8000 円以下のはずです。`max_price` を外した同じ質問も実行し、上限を超える商品が消えることを確かめてください。何も変わらない絞り込みは、効いていることを確かめたことになりません。サンプル商品での実測は次のとおりです。

| `max_price` | `keyword` | `vector` | `hybrid` |
|:---|:---|:---|:---|
| 指定なし | 青いカジュアルスニーカー ¥6800、赤いランニングシューズ ¥8900、赤いスポーツシューズ ¥7500、赤いトレーニングシューズ ¥9800 | 赤いスポーツシューズ ¥7500、赤いランニングシューズ ¥8900、赤いトレーニングシューズ ¥9800、青いカジュアルスニーカー ¥6800、軽量ビジネスバッグ ¥12000 | 青いカジュアルスニーカー ¥6800、赤いスポーツシューズ ¥7500、赤いランニングシューズ ¥8900、赤いトレーニングシューズ ¥9800、軽量ビジネスバッグ ¥12000 |
| `8000` | 青いカジュアルスニーカー ¥6800、赤いスポーツシューズ ¥7500 | 赤いスポーツシューズ ¥7500、青いカジュアルスニーカー ¥6800 | 赤いスポーツシューズ ¥7500、青いカジュアルスニーカー ¥6800 |

注目したいのは vector の列です。上限を付けると 5 件から 2 件に減ります。条件を満たす文書が 2 件しかないためです。k-NN 検索の後で絞り込んでいたら、元の 5 件のうち残ったものだけが返っていたはずです。

## 機能 2: なぜ一致したのかを説明させる

`hybrid` はすでに `keyword_score` と `vector_score` を返しています。この数値を人が読める形にします。

```text
hybrid の結果に match_reason を追加してください。2 つのスコアをもとに、語が一致した
のか、意味が一致したのか、その両方なのかを短く示すものです。
```

### 動作を確認する

```bash
curl -s -X POST http://localhost:8002/search \
  -H 'Content-Type: application/json' \
  -d '{"query": "景色をきれいに写す道具", "mode": "hybrid"}'
```

キーワード検索では見つからなかった結果が、そのことを示しているはずです。

## 回答が間違っていたら

間違うことはあります。やり直させるより、どこが違うかを伝える方が早く済みます。

```text
フィルターが k-NN 検索の後に適用されているので、絞り込むと top_k より少ない件数しか
返りません。knn クエリの中で適用してください。
```

Bob は直前に編集したファイルの文脈を保持しているので、指摘は書き直しより安く済みます。変更を丸ごと捨てたいときは、`git diff` で何が触られたかを確認できます。

!!! tip "PC 全体の走査が始まったら"

    Bob は道具を探しにいくことがあります。こちらの実行では、テストランナーを探して
    ファイルシステム全体に `find` をかけ始めました。時間がかかるだけで、ここでは得るものが
    ありません。++esc++ で止めてください。すでに適用された変更はそのまま残ります。

!!! tip "理由を聞いてみる"

    ```text
    なぜフィルターを検索後ではなく knn 句の中に入れたのですか。
    ```

    返ってくる説明は、Building Block のルールが k-NN のフィルターについて述べていることの要約になっています。一度読んでおく価値があります。

## いま起きたこと

ハイブリッド検索エンジンを、普通の言葉で 2 回変更しました。しかも変更が入ったのは、OpenSearch で間違えやすい箇所です。その専門知識は、IBM が配布していて、zip を展開するだけで導入できたモードから来ています。
