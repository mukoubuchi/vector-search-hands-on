# Vector Search ハンズオンへようこそ

このハンズオンでは、1 つの **OpenSearch** インデックスに対して、同じ質問をキーワード・ベクトル・ハイブリッドの 3 通りで検索する商品検索 API を作ります。埋め込みベクトルは **IBM watsonx.ai** で生成し、実装は **IBM Bob** に任せます。Bob には、OpenSearch のベクトル検索の作法をあらかじめ知っている **Building Block** を読み込ませます。

!!! info "前提条件"

    IBM Bob が既にインストールされていることを前提とします。このハンズオンは別々の 2 つの IBM 製品を扱い、Bob を操作する手順はどちらの製品でも書いてあります。

    - **IBM Bob IDE**（デスクトップ版）— バージョン **2.1.0**
    - **Bob shell**（コマンドライン）— バージョン **2.0.4**

    この 2 つは別製品でリリース系列も別なので、バージョン番号は一致しません。手元にある方をお使いください。

## 何を作るか

`/search` エンドポイントを 1 つ持つ FastAPI のサービスです。`mode` パラメーターで検索方式を切り替えます。

| モード | 並べ替えの方法 | 「赤いスニーカー」で「赤いランニングシューズ」が見つかるか |
|:---|:---|:---|
| `keyword` | 商品テキストに対する BM25 | 語が一致したときだけ |
| `vector` | watsonx.ai の埋め込みに対する k-NN | 見つかる。意味で一致するため |
| `hybrid` | 両方を正規化して合成 | 見つかる。しかも語の一致も効く |

3 つのモードは同じインデックスを共有します。結果の違いはデータの違いではなく、検索の仕方の違いです。

## Building Blocks とは

**Building Blocks** は、IBM の技術スタックを使った事前構築済みの技術コンポーネントです。このハンズオンでは、そのうちの 1 つを IBM が公開しているそのままの形で使います。

**OpenSearch Vector Search Builder** — IBM Bob のカスタムモードとスキルの組です。出典は [ibm-self-serve-assets/building-blocks](https://github.com/ibm-self-serve-assets/building-blocks) です。

**提供されるもの**:

- k-NN インデックスの設計、HNSW のパラメーター、`knn_vector` のマッピング、ハイブリッド検索のスコア正規化を知っている Bob のペルソナ
- 空のクラスターからハイブリッド検索が動くまでのワークフロー
- 埋め込みには IBM watsonx.ai を使い、存在しないエンドポイントやモデルを作り出さない、という指針

**このハンズオンでの同梱方法**: モード・ルール・スキルは上流のファイルをバイト単位でそのまま同梱しています。ただし 1 行だけ例外があります。上流の記述が YAML として不正なためです。コミット、blob の SHA、変更した箇所は[事前準備のこの節](preparation.md#building-block)に記録してあり、CI がビルドのたびに上流のファイルを取り直して、ほかに差分が無いことを検査します。

## Building Blocks と IBM Bob の価値

意味で検索する機能の検索層を作る作業は、その大半が決めごとです。どのエンジンを使うか、どの埋め込みモデルにするか、2 つの順位付けをどう合成するか。Building Block は、それらを決め終えた状態で届きます。

**Building Blocks が無い場合**

![Building Blocks なしの開発フロー](images/without-building-blocks-ja.svg)

OpenSearch の k-NN のドキュメントを読み、エンジンと空間タイプを選び、watsonx.ai にどのモデルがあって何次元を返すのかを調べ、ハイブリッド検索の順位がおかしくなって初めてスコア正規化の問題に出会います。

**Building Blocks ＋ IBM Bob の場合**

![Building Blocks ＋ IBM Bob の開発フロー](images/with-building-blocks-ja.svg)

モードを展開し、欲しい機能を説明し、IBM Bob の提案を確認します。決めごとは Building Block と一緒に届くので、注意を向ける先は「結果が正しいかどうか」になります。

!!! note "図の所要時間について"

    図が示しているのは、この種の機能を作るのにかかる時間であって、この研修の時間ではありません。ハンズオン自体が約 60 分で済むのは、商品データも質問もクラスターも用意してあるからです。

## ベクトル検索とは

キーワード検索は文字を照合します。ベクトル検索は意味を照合します。

商品の説明文は、埋め込みモデルによって数値の並び——**ベクトル**——に変換されます。意味の近いテキストは近いベクトルになるため、「運動するときに履くもの」は、語が 1 つも共通していなくても「ランニングシューズ」の近くに配置されます。OpenSearch はこのベクトルを `knn_vector` フィールドに保存し、近いものを探します。

どちらかが常に優れているわけではありません。

- キーワード検索は厳密です。型番、ブランド名、利用者が書いたとおりの色——こうした語は BM25 が確実に拾い、ベクトル検索はむしろ外すことがあります。
- ベクトル検索は寛容です。カタログに載っている語を 1 つも使わずに欲しいものを説明した質問は、埋め込みでしか当たりません。
- **ハイブリッド**は両方を実行して順位を合成します。実運用の検索はたいていこれです。

Part 1 では、同じ質問を 3 方式で実行して、それぞれがどこで失敗するかを見ます。

## 既存の DSCE アセットとの違い

DSCE のカタログには、すでにベクトル検索のデモがあります（Orbital Suppliers、NexusIQ、Maximo Knowledge Hub など）。このハンズオンはそれらとは種類の違う成果物です。

- **デモではなく、キットです**。このリポジトリだけで完結します。コンテナ 1 つ、スクリプト数本、手元にある資格情報だけで、誰でも同じ手順を再現できます。
- **Building Block そのものが主役です**。モードとスキルは無改変で同梱しているので、体験するのは IBM が公開しているものであって、この研修用に書き換えた別物ではありません。
- **比較が学びの中身です**。同じインデックス・同じ質問に対して、キーワード・ベクトル・ハイブリッドを並べて比べます。
- **役に立つ最小の構成で止めています**。オブジェクトストレージからの取り込み、チャンク分割、生成の工程は含めません。検索の層だけに絞ることで、動いている部品が見える状態を保ちます。
